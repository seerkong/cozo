# Business Ontology Semantic Synthesis

Keep the source database and accepted ontology immutable. Use a copied database and the read-only investigation surface; a missing investigation command is a recorded environment gap, not permission to reindex the original.

1. Collect complete evidence pages and bounded domain packs; keep their raw returned material.
2. Synthesize candidates in the v5 shape: BO summaries and local details, plus separate Associations, BusinessProcesses, DomainPolicies, EventContracts, EvidenceCatalog, and RuntimeBindings.
3. Require every candidate declaration to reference an `Evidence` whose direct text contains the reviewable code/document/database material. IDs, topology and confidence alone are insufficient.
4. Classify the portable declarative subset separately from extension points. Do not publish target code as ontology meaning.
5. Run an action-coverage pass for every BO before criticism: investigate command/controller/service/callback entry points and write effects. An object with properties but no examined write paths must be reported as incomplete, not published as actionless.
6. Run an independent critic against evidence strength, BO ownership, cross-BO placement, missing action coverage, projection leakage, gaps, and unsupported lifecycle/process claims.
7. Publish only pending review bundles with provenance, unresolved gaps, and critic outcomes. `keep` never means accepted or promotable without a separate review workflow.
