# Mission：AI 主动业务本体重建

## 背景

`add-onto-business-ontology-projection` 已建立可重复的基础能力：将索引后的代码事实投影为独立的 `onto_*` 记录，并通过 ontology XML DSL 导出。其当前的 v2/v3 assisted 实验刻意只把一个有界证据包交给 Codex，并仅接纳通过严格校验的关系、规则和生命周期候选。真实 smoke 已证明传输与校验边界可靠，但模型保守地没有提出新增候选。这是安全的，却不足以重建遗留系统中继承而来、混乱且不一致的业务模型。

下一步不是扩大一次性提示词，而是建立受控调查过程：AI 可以就已索引事实提出有界领域问题，形成假设、继续检索佐证、识别冲突，并生成可审核的候选本体和诊断制品。

## 目标

- 为 `ck_*`、`depa_*`、`judgment`、`CodeAnchor` 与 `onto_*` 事实提供只读、有界的调查面。
- 将 AI 的观察、假设、冲突、缺口、候选本体和运行 provenance 与已接纳的业务本体分开持久化。
- 创建一个在 token、查询次数和源码片段预算下执行证据优先探索、验证、协调和 XML 建模的 skill。
- 复用 `ontology-xml-dsl` 输出候选本体，并增加面向历史模型缺陷的配套诊断报告。
- 在数据库副本上执行两个仓库的真实 v2 实验；在任何 v3 扩展前，使其业务价值和不确定性可审阅。

## 非目标

- 不向模型开放任意 SQL、无限制源码树、凭据或外部工具。
- 不将 AI 输出视为证据，也不自动提升为已接纳的 `onto_*` 记录。
- 不替代确定性投影、DEPA 分析或既有的人工审核/提升边界。
- 不在本 mission 中实现 `onto_*` 与 `depa_*` 的互相标注。
- 不承诺仅凭代码即可推断所有遗留业务规则。

## 为什么需要独立 Mission

该能力横跨数据查询合同、新的持久化分析状态、agentic skill、DSL/诊断制品、真实项目实验和人工验收。这些是需要反馈驱动重规划的独立 tracks，而不是现有投影 mission 的若干 phase。现有 mission 仍是基础，其 G6 实验仍是有价值的反例证据，但无需重写才能启动本 mission。

## 成功判据

- agent 只拥有有界、带 provenance 的只读领域工具；每个候选都能枚举证据 ID 与调查步骤。
- 候选本体、诊断输出和 accepted `onto_*` 状态在物理和语义上隔离。
- 一次真实 v2 运行产生可审阅的 bundle，清楚区分观察、假设、缺口、冲突和候选 DSL 项；零候选必须如实报告，不能伪装成成功。
- 审核者可以接受、拒绝、暂缓或要求补证每个候选，无需手工重建其源码轨迹。
- v2 报告提供可测量的成本、查询/用例覆盖、证据覆盖、误报发现和接纳结果，足以决定 v3 的范围。

## 执行边界

这个 pending mission 仅规划期望态。用户确认本报告后，代码、测试、schema 变更、CLI/MCP 面与 skill 只会通过 `mission.xml` 所链接的候选 tracks 实现。
